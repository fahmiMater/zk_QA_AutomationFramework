# Automation UI Standard

> **Purpose**
>
> This document defines the official automation contract between the ERP UI platform and the ERP Automation Platform.
>
> Every UI component generated by the Metadata Rendering Engine must comply with this standard.

---

# Scope

This standard applies to all UI components generated by the ERP platform, including but not limited to:

* Pages
* Grids
* Dialogs
* Toolbars
* Tabs
* Dropdowns
* Forms
* Inputs
* Buttons
* Trees
* Menus

---

# Design Goals

The automation contract must provide:

* Stable selectors
* Technology independence
* Predictable behavior
* Consistent naming
* Metadata-driven automation

---

# Guiding Principles

The automation platform must never depend on:

* Angular generated attributes
* PrimeNG CSS classes
* Dynamic IDs
* DOM structure

Instead, automation must rely on stable metadata generated by the rendering engine.

---

# Standard Attributes

## data-automation-id

### Purpose

Provides a unique identifier for a UI element.

### Rules

* Must be unique within the current page.
* Must remain stable across releases.
* Must not contain generated values.

### Example

```html
<div
    data-automation-id="permissions-grid">
</div>
```

---

# data-automation-role

### Purpose

Defines the UI component type.

### Allowed Values

```text
page

grid

dialog

toolbar

tabs

dropdown

button

textbox

textarea

checkbox

radio

tree

menu

form

lookup
```

### Example

```html
<div
    data-automation-role="grid">
</div>
```

---

# data-automation-column

### Purpose

Identifies a grid column.

### Rules

* Must match the business column name.
* Must remain stable.

### Example

```html
<th
    data-automation-column="المعرف">
```

---

# data-automation-action

### Purpose

Identifies an executable UI action.

### Examples

```text
save

delete

edit

search

refresh

close

approve

reject

export
```

### Example

```html
<button
    data-automation-action="save">
```

---

# data-automation-field

### Purpose

Identifies a business field.

### Example

```html
<input
    data-automation-field="currency">
```

---

# data-automation-tab

### Purpose

Identifies a tab.

### Example

```html
<button
    data-automation-tab="صلاحيات العمليات">
```

---

# data-automation-dialog

### Purpose

Identifies a dialog.

### Example

```html
<div
    data-automation-dialog="add-permission">
```

---

# data-automation-grid

### Purpose

Identifies a grid instance.

Required when multiple grids exist on the same page.

### Example

```html
<div
    data-automation-grid="permissions">
```

---

# data-automation-filter

### Purpose

Identifies filter controls.

### Values

```text
button

operator

input

apply

clear
```

### Example

```html
<button
    data-automation-filter="button">
```

---

# data-automation-row-id

### Purpose

Provides a stable identifier for a business row.

### Example

```html
<tr
    data-automation-row-id="1399">
```

---

# Naming Rules

Attribute values should:

* Use kebab-case.
* Be business-oriented.
* Avoid UI terminology.
* Avoid generated identifiers.

Preferred

```text
permissions-grid

journal-entry

currency-dropdown
```

Avoid

```text
table1

grid2

p-table

div42
```

---

# Stability Requirements

Automation attributes must remain stable even if:

* Angular version changes.
* PrimeNG version changes.
* HTML structure changes.
* CSS classes change.

Breaking an automation attribute is considered a breaking change.

---

# Rendering Engine Responsibilities

The Metadata Rendering Engine must automatically generate automation attributes.

Application developers should not manually create automation attributes.

---

# Framework Responsibilities

The Automation Platform must locate UI elements exclusively through the automation contract whenever possible.

Framework components should never depend on:

* PrimeNG classes
* Angular generated IDs
* DOM hierarchy

unless no automation attribute exists.

---

# Example

Grid

```html
<div
    data-automation-role="grid"
    data-automation-grid="permissions">

    <table>

        <th
            data-automation-column="المعرف">

        <button
            data-automation-filter="button">

    </table>

</div>
```

---

# Versioning

This document defines the official Automation Contract.

Changes to this standard require:

* Architecture Review
* Approval
* Version update

Breaking changes require migration planning.

---

# Compliance Checklist

Every generated UI component should satisfy the following:

* [ ] Has a stable `data-automation-id`.
* [ ] Has the correct `data-automation-role`.
* [ ] Exposes business fields through automation attributes.
* [ ] Exposes business actions through automation attributes.
* [ ] Avoids generated identifiers.
* [ ] Avoids UI framework specific attributes.
* [ ] Remains stable across releases.

---

# Vision

The ERP Automation Platform interacts with the ERP UI through a stable Automation Contract rather than through HTML implementation details.

This allows the UI implementation to evolve independently while preserving a stable automation API.
