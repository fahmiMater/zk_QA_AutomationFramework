# كيفية تشغيل الاختبارات بفعالية

يقدم Playwright خيارات متعددة لتشغيل الاختبارات تتناسب مع الاحتياجات المختلفة، سواء كنت تقوم بالتطوير والتنقيح محلياً (Debugging) أو تشغيل الاختبارات ضمن مسارات التكامل المستمر (CI/CD).

في هذا الدليل (How-To)، سنتعرف على أهم الأوامر والطرق لتشغيل الاختبارات.

## 1. وضع واجهة المستخدم (UI Mode)
**متى تستخدمه؟** أثناء التطوير المحلي، الاستكشاف، وتصحيح الأخطاء (Debugging).
**المميزات:** واجهة تفاعلية، مشاهدة الاختبار خطوة بخطوة، Time-travel trace، والوصول لسجلات الشبكة.

```bash
npx playwright test --ui
```

## 2. الوضع المخفي (Headless Mode)
**متى تستخدمه؟** الوضع الافتراضي، يُستخدم لتشغيل الاختبارات في الخلفية بسرعة، أو في خوادم CI/CD.

```bash
npx playwright test
```

## 3. تشغيل ملف اختبار محدد أو مجلد
إذا كنت تعمل على ميزة معينة ولا تريد تشغيل كافة الاختبارات، يمكنك تمرير مسار الملف:

```bash
# تشغيل ملف محدد
npx playwright test apps/erp/demo/tests/demo.spec.ts

# تشغيل كافة الاختبارات داخل مجلد محدد
npx playwright test apps/erp/finance/
```

## 4. تشغيل الاختبارات الخاصة بـ API (بدون UI)
يحتوي الإطار على مشروع فرعي (Project) مخصص في `playwright.config.ts` باسم `api` يقوم بتشغيل ملفات الاختبار التي تنتهي بـ `-api.spec.ts`.
لتشغيلها فقط:

```bash
npm run test:api
# أو
npx playwright test --project=api
```

## 5. تغيير البيئة (Environment)
بشكل افتراضي، يتم تشغيل الاختبارات على بيئة QA (باستخدام ملف `.env.qa`). لتغيير البيئة المستهدفة، يمكنك تعيين متغير البيئة `TEST_ENV`:

```bash
# في أنظمة Windows PowerShell
$env:TEST_ENV="stage"; npx playwright test

# في أنظمة Linux/Mac
TEST_ENV=stage npx playwright test
```

يقوم الملف `playwright.config.ts` بقراءة المتغير وتحميل ملف `.env.<environment>` المناسب، مما يسمح باختبار بيئات مختلفة (مثل QA، Stage، Prod) بسهولة تامة.
