# مرجع واجهة برمجة الإطار (Framework API Reference)

هذا المستند هو مرجع شامل للوظائف والأدوات الأساسية (Core Utilities) المتوفرة في إطار الأتمتة والموجودة في مجلد `framework/core/`. الهدف من هذه الأدوات هو توحيد طريقة التعامل مع Playwright وتقديم دوال مساعدة موثوقة للاختبارات.

## 1. التعامل مع الانتظار `WaitUtils`
لا ينبغي إطلاقاً استخدام أوقات الانتظار الثابتة (مثل `waitForTimeout`). الإطار يوفر `WaitUtils` للتعامل مع الانتظار الديناميكي بذكاء.
موجود عادة في `framework/core/waits/` (أو مسار مشابه).

**دوال شائعة:**
- `WaitUtils.waitForElementVisible(locator)`: ينتظر حتى يصبح العنصر مرئياً للمستخدم بشكل كامل.
- `WaitUtils.waitForElementEnabled(locator)`: ينتظر حتى يتم تفعيل العنصر (غير Disabled).
- `WaitUtils.waitForNetworkIdle(page)`: ينتظر استقرار الشبكة لضمان اكتمال تحميل البيانات من الـ API (استخدمه بحذر، ويفضل انتظار استجابة محددة).

## 2. إدارة التوكيدات (Assertions)
يقوم الإطار بمركزة التوكيدات (Assertions) بحيث لا تتبعثر دوال `expect` العارية في جميع أنحاء كود التطبيق.
موجود عادة في `framework/core/assertions/`.

**أمثلة لتوكيدات قياسية يمكن العثور عليها:**
- `GridAssertions.rowCount(grid, expectedCount)`: يتحقق من أن عدد الصفوف في الجدول يطابق العدد المتوقع.
- `DialogAssertions.isVisible(dialog)`: يتأكد من ظهور نافذة منبثقة معينة على الشاشة.

## 3. أدوات واجهة برمجة التطبيقات (API Client)
يدعم الإطار اختبارات الـ API (الـ Services) عبر كلاس مخصص يسهل استدعاء النقاط الطرفية (Endpoints) ومعالجة الردود، وهو متواجد في `framework/core/api/ApiClient.ts`.

**المميزات الأساسية:**
- إنشاء الطلبات بشكل موحد (GET, POST, PUT, DELETE).
- التعامل التلقائي مع الـ Tokens وإضافة الـ Headers اللازمة للتوثيق (Authorization).
- استخراج وقراءة استجابات JSON بسهولة.
- تكامل مع الأنواع المتولدة من Swagger.

## 4. المسجلات وأدوات التقرير (Logger & Reports)
متواجد في `framework/core/logger/`.
لضمان تتبع سهل للأخطاء أثناء تنفيذ الاختبارات المخفية (Headless):
- يقدم دوال لتسجيل الخطوات التي تتم في الاختبار (Info, Error, Warning).
- يمكن تكامله مع تقارير Playwright (أو Allure إذا تم إعداده) لإرفاق السجلات مع كل خطوة.

## 5. محرك تحديد العناصر `AutomationLocator`
متواجد في `framework/core/locators/`.
- محرك يوفر آلية موحدة لاستخراج الـ Locators بناءً على `data-automation-id`.
- يمكن للمكونات الاستفادة منه مباشرة بدلاً من كتابة الـ CSS Selectors يدوياً في كل كلاس، مما يقلل الأخطاء.
