# هيكلية المجلدات في المشروع (Directory Structure)

يعتمد مشروع الأتمتة على فصل الاهتمامات (Separation of Concerns)، مما يضمن عدم تداخل منطق الأعمال (Business Logic) مع منطق التعامل المباشر مع المتصفح والـ UI. هذا المستند يوضح الهيكلية الرئيسية لمجلدات المشروع ووظيفة كل منها.

## الهيكل العام للمشروع

```text
QA-Automation-ERP-GL/
├── apps/               # الكود الخاص بمجال الأعمال والتطبيق (Domain-specific)
├── framework/          # المحرك الأساسي للإطار (The Core Engine)
├── tests/              # اختبارات المحرك نفسه (Framework Tests)
├── docs/               # توثيق المشروع (Diataxis Documentation)
├── playwright/         # الإعدادات وملفات المصادقة (.auth) الخاصة بـ Playwright
├── scripts/            # سكريبتات مساعدة للنظام (Tools & Generators)
├── package.json        # مدير الاعتمادات والنصوص التنفيذية
└── playwright.config.ts # إعدادات Playwright الأساسية
```

---

## 1. مجلد التطبيقات `apps/`
يحتوي هذا المجلد على كل ما يخص تطبيقات الـ ERP الفعلية. هذا هو المكان الذي نكتب فيه اختباراتنا ونمذجة صفحاتنا (Page Objects) واختبارات الـ API.
مثال لهيكلية التطبيق داخل `apps/erp`:
- `demo/`: تطبيق تجريبي للتدريب.
- `finance/`: تطبيق الإدارة المالية.
- `authentication/`: مسارات تسجيل الدخول والمصادقة.

**داخل كل تطبيق فرعي، ستجد عادة:**
- `pages/`: كلاسات تمثل الشاشات الفعلية (مثل `InvoicePage`). تستخدم المكونات الموجودة في الإطار الأساسي للتفاعل مع الواجهة.
- `tests/`: ملفات الاختبار الفعلية (الملفات التي تنتهي بـ `.spec.ts`).
- `api/`: الخدمات (Services) والـ Schemas المستخدمة في اختبارات الـ API.

---

## 2. مجلد الإطار `framework/`
يحتوي على "المحرك" الأساسي (Core Engine) الذي يشغل كل شيء. **يجب ألا يحتوي هذا المجلد على أي كود يخص منطق الأعمال أو الشاشات المحددة للـ ERP.**

أبرز محتوياته:
- `core/`: الأدوات الأساسية والقلب النابض (API Client، WaitUtils، Locators، Logger). 
- `components/`: المكونات القابلة لإعادة الاستخدام في الواجهة (Grid، Dialog، Tabs، Button، Dropdown).
- `analytics/`, `tracking/`, `reporting/`: أدوات لجمع بيانات التنفيذ والتقارير.

---

## 3. مجلد اختبارات الإطار `tests/`
(ملاحظة هامة: هذا المجلد **ليس** لاختبارات تطبيق הـ ERP).
هذا المجلد مخصص للمطورين الذين يعملون على تطوير الإطار (Framework) نفسه. يحتوي على Unit Tests أو Integration Tests مصممة للتأكد من أن كلاسات `WaitUtils`، أو `ApiClient`، أو الـ `Components` تعمل بكفاءة ولم يتم كسرها.
يتم تشغيلها باستخدام `npx playwright test --project=framework`.

---

## 4. المجلدات الأخرى 
- `playwright/`: يستخدمه Playwright لحفظ ملفات حالة المتصفح (مثل `user.json` في مجلد `.auth` لتخزين جلسات تسجيل الدخول وتسريع الاختبارات).
- `scripts/`: مجلد يحتوي على أكواد مساعدة مثل سكربتات لتوليد الأنواع (Types) من الـ Swagger، أو مسح قاعدة البيانات.
